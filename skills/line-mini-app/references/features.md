```
│ (A) Header                  │  ← Platform-native, auto-generated by LINE
│  [←] Service Name    [⋯][×] │
├─────────────────────────────┤
│ (B) Body                    │  ← WebView, your HTML5 + LIFF code
│                             │
│                             │

```

### Header Components

| # | Component | Description |
|---|-----------|-------------|
| 1 | **Service Name** | From page `<title>` element. Cannot set font |

| LINE Version | Unverified | Verified |

#### Minimized Display (Updated December 2025, LINE ≥15.20.0)

- Icon displays **without background**, appearing larger for better brand visibility
- Default position: **right-center** of screen (previously variable)
- Position is **remembered across sessions** and different MINI Apps
- Close via dedicated **X button** (top-right) — drag-to-close removed
- First-time users see "tap to confirm" guidance overlay
- Applies to both LINE MINI Apps and LIFF apps

See [Minimizing LIFF browser](https://developers.line.biz/en/docs/liff/minimizing-liff-browser/).

### Body

WebView container. Use HTML5 and LIFF APIs. Almost all HTML5 specs supported (Geolocation, Maps, Media, etc.).

### Loading Icon

LINE provides official animated spinner SVGs for use as loading indicators. Using these spinners is recommended for visual consistency.

| Variant | Stroke color | Download |
|---------|-------------|----------|
| Light mode | `#b7b7b7` (gray) | [LINE_spinner_light.svg](https://developers.line.biz/media/line-mini-app/LINE_spinner_light.svg) |
| Dark mode | `#fcfcfc` (near-white) | [LINE_spinner_dark.svg](https://developers.line.biz/media/line-mini-app/LINE_spinner_dark.svg) |

- Alignment: **center-aligned** horizontally

## Built-in Features

### Action Button

Always displayed in the header. **Cannot be hidden** (Module mode unavailable for MINI App channels).

Tapping opens the **multi-tab view** (LINE ≥15.12.0) with:
1. Options for the current MINI App
2. Recently used services (up to 50 items)

### Multi-Tab View Options

| Option | Description | Availability |
|--------|-------------|-------------|
| **Refresh** | Reload current page | All |
| **Share** | Share current page as LINE message (permanent link + title + icon) | All (older LINE shares top page only) |
| **Add to Home** | Add shortcut to device home screen. URL must start with endpoint URL | Verified, LINE ≥14.3.0 |
| **Favorites** | Add to Wallet tab in LINE app | Verified, Japan, LINE ≥15.18.0 |
| **Minimize** | Minimize LIFF browser | Verified |
| **Permission settings** | View/change camera & mic permissions. Changes may need page reload | LINE ≥14.6.0 |
| **About the service** | Display Provider page | Verified |
| **Report** | Open inquiry form in external browser | Japan, LINE ≥15.6.0 |

### Channel Consent Simplification

Simplifies permission consent when users access a LINE MINI App for the first time. Based on LY Corporation's privacy policy, only the **`openid` scope** (user ID) is auto-skipped. Other scopes (`profile`, `chat_message.write`, `email`) require per-app consent via a **verification screen**.

#### Two-Step Authorization Flow (When Enabled)

**Step 1 — Simplification consent screen**: On first-ever LINE MINI App access, users are asked to allow getting their user ID (`openid` scope). Tapping "Agree" also consents for all other simplification-enabled MINI Apps.

- Tapping **"Not now"**: consent is skipped; individual channel consent screens are shown instead. After **24 hours**, the simplification screen is shown again

**Step 2 — Verification screen**: Displayed when executing methods that require scopes beyond `openid`:

| Scope | Triggered by |
|-------|-------------|
| `email` | `liff.getIDToken()`, `liff.getDecodedIDToken()` |
| `profile` | `liff.getProfile()`, `liff.getFriendship()` |
| `chat_message.write` | `liff.sendMessages()` |

Use `liff.permission.query()` and `liff.permission.requestAll()` to proactively display the verification screen:

```javascript
liff.permission.query("profile").then((permissionStatus) => {
  if (permissionStatus.state === "prompt") {
    liff.permission.requestAll();
  }
});
```

> **Design tip:** The verification screen is shown only when non-`openid` permissions are needed, not at launch. If your MINI App calls `liff.getProfile()` immediately after launch, it appears as if the consent screen wasn't skipped. Execute such requests only when actually needed.

#### Operating Conditions

All must be met:
- LINE MINI App is **verified** (for unverified, works only in Developing and Review channels)
- LIFF SDK **v2.13.x or later**
- Not opened via **LIFF-to-LIFF transition**

#### Known Issues

- **ID token pitfall**: If your app calls the "Verify ID token" endpoint to get profile info, the ID token payload won't include profile info because the `profile` scope was skipped. Solution: display the verification screen first using `liff.permission.query()` / `liff.permission.requestAll()`
- **Add friend option conflict**: If only `openid` is specified in Scope and simplification is enabled, verification/consent screens never appear → can't prompt friend add. Solution: specify scopes other than `openid` and display the verification screen
- **Quick-fill conflict**: If both Quick-fill and Channel consent simplification are enabled, users cannot disable the Common Profile toggle on the consent screen. A fix is planned

#### Setup

See [console-setup.md § Channel Consent Simplification Setup](console-setup.md#channel-consent-simplification-setup).

For more information, see [Channel consent simplification](https://developers.line.biz/en/docs/line-mini-app/develop/channel-consent-simplification/).

## Custom Features

### Custom Path

Set a custom string in the published LIFF URL instead of the LIFF ID. Users can identify the brand or shop directly from the URL. Verified MINI Apps only.

```
Before: https://miniapp.line.me/123456-abcdefg
After:  https://miniapp.line.me/cony_coffee
```

The original LIFF ID URL remains accessible after the Custom Path is set.

#### How to Apply

| Region | Process | Turnaround |
|--------|---------|-----------|
| Japan | Submit [application form](https://form-business.yahoo.co.jp/claris/enqueteForm?inquiry_type=lmini-custompath). Supports multiple MINI Apps at once | 1–2 weeks |
| Taiwan / Thailand | Contact your sales representative | — |

- Can apply before review, but the Custom Path is only activated **after the channel passes review**
- Once set, the path **cannot be changed** in principle
- Custom Path URL is **not shown** on the LINE Developers Console

#### String Restrictions

- **4–29 characters**; lowercase alphanumeric (`a-z`, `0-9`) and underscore (`_`) only
- Underscore cannot be the last character; cannot be numeric only; no spaces
- Must include a proper noun identifying the brand/service
- Cannot duplicate LY Corporation service strings or strings already in use
- Inappropriate strings may be rejected

### Home Screen Shortcut

Users can add a shortcut to their device home screen for quick access. Useful for frequently used services (membership cards, mobile ordering).

Verified MINI Apps only (unverified can test on Developing channel), LINE ≥14.3.0.

#### Trigger Methods

Two ways to display the Add Shortcut screen:
1. Tap **"Add to Home"** in the multi-tab view (via action button)
2. Call `liff.createShortcutOnHomeScreen()` method programmatically

#### iOS Compatibility

| Default browser | iOS version | Works? |
|----------------|------------|--------|
| Safari | All versions | ✅ |
| Chrome | ≥ 16.4 | ✅ |
| Other browsers | ≥ 16.4 | Not guaranteed |
| Non-Safari browsers | < 16.4 | ❌ (error page shown) |

**Android note:** On some devices, changing the LINE app icon via Settings > App icon may remove existing shortcuts.

See [Add a shortcut to home screen](https://developers.line.biz/en/docs/line-mini-app/develop/add-to-home-screen/).

### Custom Action Button

The built-in action button in the **header** is implemented by LINE and cannot be customized. To send custom share messages, implement a custom action button in the **body**.

#### Share Target Picker

Tapping the custom button opens the **target picker** (screen for selecting a group or friend). The user selects a recipient and sends a customized Flex Message.

See [Sending messages to a user's friend](https://developers.line.biz/en/docs/liff/developing-liff-apps/#share-target-picker).

#### Custom Share Message Format

Use a **Bubble** container of Flex Message. **Do not** use a Carousel container.

Two format types: **standard** and **image list**, both composed of sections A–F:

| Section | Required | Description |
|---------|----------|-------------|
| A — Image | Optional | Hero block image. `aspectRatio` height ≤ width × 2 |
| B — Title | ✅ | Summarize content. Max 2 lines, size `lg`, color `#000000`, weight `bold` |
| C — Subtitle | * | Subtitle. Max 2 lines, size `sm`, color `#999999` |
| D — Detail | * | Label-description list. Standard: max **10 items**. Image list: max **5 items** |
| E — Button | ✅ | Up to **3 buttons**. At least one must link to a detail page. Use permanent links for non-top pages |
| F — Footer | ✅ | MINI App icon + name + `>` image ([fixed URL](https://vos.line-scdn.net/service-notifier/footer_go_btn.png)). Links to MINI App top page |

\* Must include at least C or D (may use both).

**Key rules:**
- Actions can **only** be set on buttons (E) and footer (F) components
- Primary button style only for the first button; other buttons use `link` style. `secondary` style not allowed
- Footer `>` image URL: `https://vos.line-scdn.net/service-notifier/footer_go_btn.png` — do not change

For full JSON examples, see [Share message guidelines (standard)](https://developers.line.biz/en/docs/line-mini-app/develop/share-messages-standard/) and [Implementing a custom action button](https://developers.line.biz/en/docs/line-mini-app/develop/share-messages/).

### OA Friend Inducement (Add Friend Option)

Display an option for users to add your LINE Official Account as a friend on the verification screen or channel consent screen. Available for both verified and unverified MINI Apps.

#### Prerequisites

All three conditions must be met:

| # | Requirement |
|---|-------------|
| 1 | LINE Official Account uses the **Messaging API** |
| 2 | Messaging API channel and LINE MINI App channel belong to the **same provider** |
| 3 | Operator holds **Admin** role on the MINI App channel AND **Administrator** role on the LINE OA |

#### Setup Steps

1. LINE Developers Console > MINI App channel > **Basic settings** tab > "Linked LINE Official Account" > Edit > Select your OA > Update
2. **Web app settings** tab > "Add friend option" > Edit > Select **"On (normal)"** > Update

#### Certified Provider Behavior

If a MINI App channel belongs to a certified provider, the add friend option is **enabled by default**. Unless users manually turn it off, the linked OA is auto-added as friend when users grant authorization.

See [Add friend option](https://developers.line.biz/en/docs/line-mini-app/service/line-mini-app-oa/#link-a-line-official-account-with-your-channel).

### Promoting via LINE Official Account

Use your LINE Official Account to drive traffic to your MINI App:

| Method | Description |
|--------|-------------|
| **Rich messages** | Send visually engaging messages that convey your MINI App's value |
| **Rich menu link** | Set your MINI App's LIFF URL or permanent link in the rich menu for direct access from OA chat |

See [Use LINE Official Account](https://developers.line.biz/en/docs/line-mini-app/service/line-mini-app-oa/).

### Payment Systems

LINE MINI App has **no built-in payment function**. Connect external payment services or use In-App Purchase.

| Method | Availability |
|--------|-------------|
| LINE Pay | **Taiwan, Thailand only** (terminated in Japan as of April 30, 2025) |
| External payment services | All regions (PayPay, Stripe, GMO Payment Gateway, etc.) |
| In-App Purchase (app store payments) | **Japan only** (requires separate application) |

> **Roadmap:** Credit payment functionality (stored payment details for frictionless transactions) is planned for **2026+**.

#### LINE Pay Integration

- Requires a **LINE Pay Merchant Account** — apply at [LINE Pay](https://pay.line.me/portal/global/main)
- Integrate using [Online payment documentation](https://developers-pay.line.me/online) in LINE Pay Developers
- Test with the LINE Pay [sandbox](https://developers-pay.line.me/sandbox)
- Recommended over credit cards to avoid prompting users for card info

#### Other Payment Methods

Implement as ordinary web pages. Must design the process so users are **redirected back to the MINI App page** after completing a transaction on an external domain or app.

See [Using payment systems](https://developers.line.biz/en/docs/line-mini-app/develop/payment/) and [in-app-purchase.md](in-app-purchase.md).

## Permanent Links

Use permanent links (not raw LIFF URLs) when sharing LINE MINI App pages — via web pages, emails, social media, rich messages, rich menus, custom action buttons, or service messages.

When sharing from the action button in the header, LINE **automatically generates** a permanent link. For all other cases, construct it manually:

### Construction Formula

```
Permanent Link = LIFF URL + (MINI App Page URL − Endpoint URL)
```

**Example:**

| Item | Value |
|------|-------|
| LIFF URL | `https://miniapp.line.me/123456-abcedfg` |
| MINI App page URL | `https://example.com/shop?search=shoes#item10` |
| Endpoint URL | `https://example.com` |
| **Permanent link** | `https://miniapp.line.me/123456-abcedfg/shop?search=shoes#item10` |

LIFF URL and Endpoint URL are found on the **Web app settings** tab in the Console. You can use path, query parameters, and hash fragments.

### LIFF URL Domain

As of December 13, 2023, the LIFF URL domain changed. The old domain still works (redirects).

| LINE app version | Generated URL domain |
|-----------------|---------------------|
| ≥ 13.20 | `https://miniapp.line.me/{liffId}` |
| < 13.20 | `https://liff.line.me/{liffId}` |

### Behavior Without LINE Installed

- **With LINE**: user is taken to the exact page
- **Without LINE**: browser opens with guidance to open in LINE; user can also open the LIFF endpoint URL directly in the browser

## External Browser Behavior

As of October 2025, LINE MINI Apps can be used in external browsers. When developing, ensure the service works in both LIFF browser and external browsers.

### Login Handling

In external browsers, `liff.init()` alone does **not** trigger LINE Login. Handle login explicitly:

**Method 1 — Auto login at initialization:**
```javascript
liff.init({
  liffId: "1234567890-AbcdEfgh",
  withLoginOnExternalBrowser: true,
});
```

**Method 2 — Login only when needed:**
```javascript
if (!liff.isLoggedIn()) {
  liff.login();
}
```

### Features NOT Available in External Browsers

| API | Note |
|-----|------|
| `liff.sendMessages()` | |
| `liff.openWindow()` | |
| `liff.closeWindow()` | |
| `liff.scanCode()` | Deprecated |
| `liff.iap.*` | All in-app purchase APIs |

When users access these features in an external browser, display a message: "To use this feature, you must open the LINE MINI App in LINE app." Use `liff.isInClient()` to detect the environment.

### APIs Available Without LINE Login

For non-LINE users accessing via external browser, these APIs work without login:

`liff.id`, `liff.ready`, `liff.init()`, `liff.getOS()`, `liff.getAppLanguage()`, `liff.getVersion()`, `liff.getLineVersion()`, `liff.isInClient()`, `liff.isLoggedIn()`, `liff.permanentLink.createUrlBy()`, `liff.use()`

> **Design principle:** Assume non-LINE users will open the MINI App. Ensure core service functionality works without requiring LINE Login.
